# Правила проекта HDREZKA Desktop

## Версионирование и документация
- При любом обновлении версии приложения (в `package.json`, `src/shared/constants/index.ts`, `src/core/providers/rezka/provider.ts`) **всегда обновлять версию в `README.md`**:
  - **Бейдж версии в шапке (под описанием)**: `[![Version](https://img.shields.io/badge/version-<версия>-crimson.svg?style=flat-square)](https://github.com/KDGOfficial/HDRezka-Desktop/releases)`
  - **Имена выходных файлов в разделе «Сборка дистрибутива»**: `HDREZKA-Setup-<версия>.exe` и `HDREZKA-Portable-<версия>.exe`
- Все изменения версий и документации обязательно фиксировать в коммитах и пушить в репозиторий.

## CI/CD и релизы на GitHub (СТРОГО ОБЯЗАТЕЛЬНО)
- **Обязательное создание GitHub Release для каждого обновления**:
  - При каждом повышении версии **СТРОГО ОБЯЗАТЕЛЬНО** создавать соответствующий git-тег `v<версия>` (например, `git tag v0.0.13` и `git push origin v0.0.13`) и публиковать официальный GitHub Release.
  - Встроенный в приложение механизм автообновления опирается на обращение к GitHub API (`https://api.github.com/repos/KDGOfficial/HDRezka-Desktop/releases/latest`). Без опубликованного релиза на GitHub клиенты приложения не узнают о новой версии и не смогут обновиться.
- **Обязательная сборка дистрибутива в CI/CD**:
  - В репозитории всегда должен быть настроен и поддерживаться рабочий GitHub Actions workflow (`.github/workflows/release.yml`), автоматически запускающий сборку приложения под Windows при пуше тегов `v*` (или ручном запуске через `workflow_dispatch`).
- **Обязательное прикрепление `.exe` артефактов к релизу**:
  - Каждый GitHub Release **обязан содержать исполняемые файлы**: инсталлятор `HDREZKA-Setup-<версия>.exe` и портативную версию `HDREZKA-Portable-<версия>.exe`.
  - Встроенный в приложение механизм автообновления опирается на прямую загрузку прикрепленного `.exe` файла.
  - Если по какой-либо причине `.exe` артефакт в релизе временно формируется на CI/CD, приложение должно безопасно и информативно открывать официальную страницу релиза в браузере без сбоев интерфейса.
- **Обязательное уведомление пользователей о доступности новой версии**:
  - Приложение обязано автоматически проверять наличие обновлений при старте и периодически во время работы.
  - При обнаружении новой версии пользователь обязательно уведомляется через всплывающее окно `UpdateModal`, верхний баннер в интерфейсе и индикаторы в заголовке/шапке.

## Механизм автообновления, перезапуск и окно «Что нового» (СТРОГО ОБЯЗАТЕЛЬНО)
- **Гарантированный перезапуск приложения после обновления**:
  - При нажатии «Установить и перезапустить» приложение обязано корректно запускать инсталлятор и перезапускать обновлённую версию программы после окончания инсталляции.
  - Закрытие приложения «в пустоту» без автоматического запуска обновлённого `.exe` категорически недопустимо. Процесс перезапуска обеспечивается фоновым updater-скриптом, ожидающим освобождения файлов предыдущим PID и запускающим целевой `HDREZKA Desktop.exe`.
- **Визуальный прогресс установки**:
  - Пользователь должен видеть наглядный статус и прогресс установки обновления (индикатор выполнения и текстовое пояснение в `UpdateModal` и на странице `Настройки`) перед перезапуском приложения.
- **Обязательный показ окна «Что нового» (Release Notes)**:
  - При первом запуске обновлённого приложения после установки пользователь обязан уведомляться всплывающим окном `WhatsNewModal` с описанием ключевых изменений и улучшений установленной версии.
