# Правила проекта HDREZKA Desktop

## 🚨 Золотое правило версионирования и релизов (СТРОГО ОБЯЗАТЕЛЬНО)
- **Каждый раз при любых изменениях обязательно повышать цифру версии приложения**:
  - При любом изменении кода, фиксе багов или добавлении новых функций **СТРОГО ОБЯЗАТЕЛЬНО** повышать версию программы (например: `0.0.13` ➔ `0.0.14`).
  - **Почему это критично для автообновления**: Встроенный в приложение механизм автообновления сравнивает текущую версию программы с последней версией на GitHub (`https://api.github.com/repos/KDGOfficial/HDRezka-Desktop/releases/latest`). Если цифра версии не была повышена, приложение посчитает, что у пользователя уже установлена актуальная версия, и автообновление **НЕ сработает**.
  - Версию синхронно обновлять во всех ключевых точках:
    1. `package.json` (поле `version`)
    2. `src/shared/constants/index.ts` (`APP_VERSION`)
    3. `src/core/providers/rezka/provider.ts` (`this.version`)
    4. `tests/spider-man.test.js` (проверка версии в юнит-тестах)
    5. `README.md` (бейдж версии и имена файлов дистрибутива в инструкции по сборке)

- **Обязательное создание GitHub Release для каждого обновления версии (ДЕЛАЙ ВСЁ САМ)**:
  - При каждом повышении версии **СТРОГО ОБЯЗАТЕЛЬНО** самостоятельно создавать коммит, соответствующий git-тег `v<версия>` (например, `git tag v0.0.17`) и пушить изменения в удаленный репозиторий: `git push origin main && git push origin v<версия>`.
  - **Полная автономность релизов**: Агент обязан выполнять весь процесс самостоятельно без ожидания подтверждения от пользователя и без откладывания («делай всё сам»). Не допускается завершать задачу словами «не создавался git-тег/релиз» — агент обязан закоммитить изменения, поставить тег и сделать push, запуская автоматический GitHub Actions workflow (`release.yml`), собирающий дистрибутив и публикующий релиз.
  - Без опубликованного на GitHub релиза клиенты приложения не увидят обновление и не смогут получить новые сборки.

## CI/CD и исполняемые файлы в релизах на GitHub (СТРОГО ОБЯЗАТЕЛЬНО)
- **Обязательная сборка дистрибутива в CI/CD**:
  - В репозитории всегда должен быть настроен и поддерживаться рабочий GitHub Actions workflow (`.github/workflows/release.yml`), автоматически запускающий сборку приложения под Windows при пуше тегов `v*` (или ручном запуске через `workflow_dispatch`).
- **Обязательное прикрепление `.exe` артефактов к релизу**:
  - Каждый GitHub Release **обязан содержать исполняемые файлы**: инсталлятор `HDREZKA-Setup-<версия>.exe` и портативную версию `HDREZKA-Portable-<версия>.exe`.
  - Встроенный в приложение механизм автообновления опирается на прямую загрузку прикрепленного `.exe` файла.
  - Если по какой-либо причине `.exe` артефакт в релизе временно формируется на CI/CD, приложение должно безопасно и информативно открывать официальную страницу релиза в браузере без сбоев интерфейса.
- **Обязательное уведомление пользователей о доступности новой версии**:
  - Приложение обязано автоматически проверять наличие обновлений при старте и периодически во время работы (каждые 30 минут).
  - При обнаружении новой версии пользователь обязательно уведомляется через всплывающее окно `UpdateModal`, верхний баннер в интерфейсе и индикаторы в заголовке/шапке.

## Механизм автообновления, перезапуск и окно «Что нового» (СТРОГО ОБЯЗАТЕЛЬНО)
- **Гарантированный перезапуск приложения после обновления**:
  - При нажатии «Установить и перезапустить» приложение обязано корректно запускать инсталлятор и перезапускать обновлённую версию программы после окончания инсталляции.
  - Закрытие приложения «в пустоту» без автоматического запуска обновлённого `.exe` категорически недопустимо. Процесс перезапуска обеспечивается фоновым updater-скриптом, ожидающим освобождения файлов предыдущим PID и запускающим целевой `HDREZKA Desktop.exe`.
- **Визуальный прогресс установки**:
  - Пользователь должен видеть наглядный статус и прогресс установки обновления (индикатор выполнения и текстовое пояснение в `UpdateModal` и на странице `Настройки`) перед перезапуском приложения.
- **Обязательное обновление описания новых функций и фиксов в окне «Что нового» (СТРОГО ОБЯЗАТЕЛЬНО ПРИ КАЖДОМ РЕЛИЗЕ)**:
  - При **КАЖДОМ** повышении версии программы агент **СТРОГО ОБЯЗАН актуализировать список нововведений** в `src/renderer/i18n/translations.ts` (секция `whatsNew` для всех поддерживаемых языков: `ru`, `uk`, `en`) и `src/renderer/components/WhatsNewModal.tsx`.
  - **Категорически запрещено** оставлять старый чейнджлог из предыдущей версии! Пользователь при первом запуске обновлённого приложения обязан видеть актуальные новые функции, фиксы багов и доработки именно установленной версии.
  - При первом запуске обновлённого приложения после установки пользователь обязан уведомляться всплывающим окном `WhatsNewModal` с описанием актуальных ключевых изменений и улучшений установленной версии.

## Архитектурные стандарты источников, качества, озвучек и браузера (СТРОГО ОБЯЗАТЕЛЬНО)
- **Открытые зеркала без капчи, автообновление и автовозврат HDRezka**:
  - Базовые открытые источники приложения: `OPEN_MIRROR_SEEDS` (`https://kinobase.org`, `https://www.kinobase.org`, `https://kinogo.film`). Запросы к CDN-потокам (`redcdn.org`, `threnet.xyz`, `mvapspdmpg.com`, `tazaromikaz.link`, `cinemar.cc`, `cinemap.cc`) должны получать корректные `Referer`, `Origin` и единый `BROWSER_USER_AGENT`.
  - Зеркала с анти-бот проверкой (`needsVerification: true`) или таймаутами (`isAvailable: false`) автоматически удаляются из активного списка в фоне (каждые 5 минут и при запуске), если доступен хотя бы 1 чистый открытый источник.
  - Оригинальные домены `HDREZKA_MIRRORS` обязательно сохраняются в фоновом пуле и перепроверяются в `findOnlineMirrors()` и `CHECK_MIRRORS`: как только любое зеркало HDRezka начинает отвечать без анти-бот защиты, оно автоматически включается обратно и получает приоритет.
  - В `src/core/providers/rezka/provider.ts` встроенные Node-модули (например, `vm`) загружаются динамически (через `process.getBuiltinModule` / `eval('require')`), чтобы не ломать esbuild-сборку юнит-тестов.
- **Фильтрация экранок (Anti-CamRip) и приоритет высокого качества (HD / FullHD / 4K)**:
  - Запрещено выводить экранки по умолчанию: функция `isCamRipText()` отсеивает релизы, озвучки и варианты балансеров с пометками `CAMRip`, `CAM`, `TS`, `TC`, `Экранка`, `ТS` при наличии чистых версий.
  - Плеер и балансеры (`usePlayerStore`, `extractBalancerStream`) по умолчанию выбирают максимальное HD/FullHD/4K качество (`1080p Ultra` -> `1080p` -> `2160p` -> `1440p` -> `720p`) без рекламы.
- **Выбор озвучки на всех зеркалах и рецензии**:
  - На странице фильма (`DetailsPage`) и в плеере (`VideoPlayer`) должен быть доступен выбор озвучки для всех источников (`Kinobase`, `Kinogo`, `HDRezka`) с кросс-зеркальным обогащением и отображением текущей активной дорожки.
  - На странице фильма обязателен раздел **«Комментарии и рецензии критиков»** (`All` / `Critics` / `Users`), объединяющий зрительские комментарии, развёрнутые рецензии и кинокритику.
- **Встроенный кино-браузер в стиле приложения (строго Google, без Яндекса)**:
  - Если фильм не найден или заблокирован, пользователю предлагается поиск во встроенном тёмном браузере (`BrowserPage`, `<webview>` с `webviewTag: true`, единым `BROWSER_USER_AGENT`, блокировкой рекламных поп-апов и кнопкой **«Открыть в плеере»** для найденной карточки фильма).
  - В качестве поисковой системы во встроенном браузере (`useMediaStore.openBrowser`, `BrowserPage.PORTALS`, `normalizeUrlOrSearch`) **СТРОГО ОБЯЗАТЕЛЬНО использовать Google (`https://www.google.com/search?q=...`)**, и **категорически запрещено** использовать Яндекс.
